# 人民币汇率全链路一致性需求文档

## 0. 评审摘要（必读）

> 本节供产品、研发、测试、财务与运营快速评审；详细规则见 `## 1` 及之后。本文只定义目标与验收，不修改任何业务代码。
> 已有套餐订阅价格问题见相邻目录 `../cny-display-conversion/prd.md`；本需求补齐钱包充值、余额显示、支付确认与管理员汇率配置的统一规则。

### 0.1 一句话需求

将「展示汇率」与「充值售价」明确分工：余额、额度和价目仅用展示汇率；用户本次充值的实付金额与到账额度仅按充值售价计算并写入订单快照，确保同一笔订单从输入到收银台金额一致、到账可解释。

### 0.2 线上现状证据（固定评审样例）

> 固定样例：内部余额 `10.00` 美元等值额度、展示汇率 `7.30`、充值售价 `¥5.00 / 1 美元等值额度`、用户输入充值 `¥12.50`。完整页面级证据见 [现状 vs 改后对照原型](./prototype-before-after.html)。

| 页面 / 字段 | 现在（线上风险还原） | 问题 |
|------|----------|------|
| 管理员配置 | “汇率”与“充值倍率”存在但用途、生效范围不透明 | 展示与支付容易混用；配置缺失时可能分别回退 `7.3`、`7`、`1` |
| 钱包余额 | `10.00 × 7.30 = ¥73.00` | 此金额仅证明展示汇率用途，不应参与本次充值支付/到账计算 |
| 添加资金 | 用户输入 `¥12.50` 可能被整数解析为 `¥12` | 人民币小数丢失，确认金额与实际意图不一致 |
| 支付确认 / 收银台 | 金额依据未固化为订单快照 | 无法证明确认页、支付请求、收银台使用同一应付金额 |
| 订单详情 | 可能读取当前售价 | 管理员改价后历史订单无法按创建时口径复核 |

### 0.3 做什么 / 不做什么

- **做什么**：统一管理员配置命名；定义余额展示、充值实付、到账内部额度、订单快照和生效边界；统一人民币金额精度；统一配置缺失时的阻断与提示。
- **不做什么**：不把内部额度账本改为人民币；不接入自动汇率服务；不重算历史订单或消费；不改变支付验签、入账幂等和渠道合同；不改变已确认的套餐额度数值。

### 0.4 核心口径

1. **展示汇率**：用于在人民币与美元等展示币种之间等值显示内部美元额度，例如余额、模型价目和用量；展示币种切换只能改变显示金额和符号，不能改变经济价值。
2. **充值售价**：用户购买 1 美元等值内部额度时的结算币种价格；用于计算充值结算金额和到账额度，可与展示汇率不同。
3. **订单快照**：创建订单时保存结算币种、结算金额、充值售价、展示币种、展示换算汇率、到账内部额度与配置版本；订单后续完成、查询和补单均使用快照，不读取新配置。
4. **金额一致性**：同一订单的充值确认页、支付入口和收银台在结算币种下的应付金额必须一致；跨币种展示时金额可按汇率等值显示，但展示币种切换不得改变结算金额、实际收款或已创建订单。

### 0.5 原型预览（评审基线）

- **唯一评审原型**：[查看现状 vs 改后页面对照](./prototype-before-after.html)
- **评审方式**：左侧为线上现状截图还原，右侧为拟交付；同屏对比管理员配置、钱包添加资金、支付确认/收银台和订单详情。
- **评审关注点**：展示汇率与充值售价允许不同；订单使用创建时的售价快照；人民币小数不截断；配置缺失时禁止创建新订单而非静默套用不同默认值。

### 0.6 关键验收

- 展示汇率从 `7.30` 改为 `7.00` 时，余额显示从 `¥73.00` 变为 `¥70.00`；本次及已创建订单的结算金额 `¥12.50` 不变。
- 充值售价从 `5.00` 改为 `5.20` 时，新订单按 `5.20` 试算；已创建订单保持结算价 `¥12.50 → 2.50` 的原快照。
- 用户输入 `¥12.50` 时，人民币展示下添加资金页、确认页、支付入口、收银台与订单详情均显示 `¥12.50`，不得变为 `¥12.00` 或 `¥13.00`；美元展示下应等值显示 `$1.71`，并注明实际收款 `¥12.50`。
- 仅切换展示币种不得改变充值结算币种、结算金额、到账内部额度或支付通道实际收款。
- 展示汇率与充值售价缺失、非正数或超出平台设定范围时，管理员无法保存；用户侧不得创建新支付订单，已创建订单仍按快照查询或完成。

## 2. 项目概述

### 2.1 背景

当前前端余额展示与充值支付分别依赖不同的配置值，配置值在业务上允许不同，但页面没有清晰说明；同时存在多套默认汇率和人民币金额整数解析，导致用户可能看到无法解释的金额差异。平台需要保留弹性定价能力，同时保证每一笔订单全程可复算、可追溯。

### 2.2 业务目标

- 用户能理解余额显示金额、充值支付金额和到账额度各自依据。
- 同一订单的确认页、支付入口与收银台不会出现不一致金额。
- 管理员调整展示汇率不影响支付售价；调整售价只影响新订单。
- 财务可按订单快照复核任一订单，无需依赖当前配置猜测历史口径。

### 2.3 范围

**范围内**：管理员汇率/售价配置；用户余额与额度展示；充值输入、确认、收银台金额；到账说明；订单价格快照；人民币金额精度和配置异常提示。

**跨 PRD 边界**：套餐订阅的应付金额、余额支付与支付通道收款一致性，直接采用 `../cny-display-conversion/prd.md` 的 CNY-001、CNY-002、CNY-008 结论；本文不重新定义套餐价格的币种含义，也不调整套餐额度。

**范围外**：自动汇率同步；内部账本币种迁移；历史订单重算；支付渠道验签与回调协议改造；套餐额度重新定价。

## 3. 角色与权限

| 角色 | 职责 |
|------|------|
| 登录用户 | 查看余额、输入充值金额、确认实付与到账额度。 |
| 平台管理员 | 配置展示汇率与充值售价，并查看配置影响。 |
| 财务/运营 | 审核售价策略与订单快照，处理用户金额咨询。 |
| 系统 | 按订单快照完成支付、入账与历史查询。 |

仅平台管理员可修改展示汇率与充值售价；配置变更必须记录操作者、时间、变更前后值。

## 4. 功能需求

### 4.1 管理员配置

#### CNYR-001：展示汇率与充值售价分离配置

**优先级**：P0

**需求描述**：管理端必须以独立字段配置展示汇率和充值售价，分别展示用途、示例与影响范围，不得使用同一个“汇率”名称混淆。

**业务规则**：

1. 展示汇率仅影响余额、额度、价目和用量的人民币显示。
2. 充值售价仅影响新建充值订单的实付金额与到账内部额度。
3. 两个值允许不同；不同不视为配置错误。
4. 两个值均必须为有限正数，精度、上限和下限由后台统一校验。

**验收标准**：

1. 管理员可同时看到两个字段及各自用途说明。
2. 管理员仅修改展示汇率并保存后，充值订单试算的应付金额不变化。
3. 管理员仅修改充值售价并保存后，余额展示不因该操作变化。

#### CNYR-002：配置变更影响预览与审计

**优先级**：P1

**需求描述**：保存前展示配置变更对余额显示、新充值订单实付/到账的示例影响；保存后保留审计记录。

**验收标准**：

1. 修改任一字段时，页面能展示“影响余额”或“影响新订单”的明确标签。
2. 变更记录包含操作者、时间、旧值、新值。
3. 已创建订单不因保存新配置而改变其快照值。

### 4.2 订单金额与到账换算

#### CNYR-003：充值订单使用售价快照

**优先级**：P0

**需求描述**：创建充值订单时，系统根据充值售价计算结算金额与到账内部额度，并将结算与展示换算依据写入订单快照。

**业务规则**：

1. 订单创建后，支付、回调、查询和补单均使用订单快照。
2. 展示汇率不得参与订单结算金额或到账内部额度计算；展示币种切换仅影响用户可见的等值金额与符号。
3. 订单快照至少包含：结算币种、结算金额、展示币种、展示换算率、充值售价、用户输入金额、到账内部额度、创建时间和配置版本。
4. 结算金额为 `¥12.50`、展示汇率为 `¥7.30 / $1` 时，美元展示为 `$1.71`，支付通道和收银台仍按 `¥12.50` 结算。

**验收标准**：

1. 当充值售价为 `¥5.00 / 美元额度`、用户支付 `¥12.50` 时，到账为 `2.50` 美元等值内部额度。
2. 当展示币种切换为美元、展示汇率为 `¥7.30 / $1` 时，同一订单应显示 `$1.71`，并注明实际收款 `¥12.50`；不得显示 `$12.50`。
3. 订单创建后管理员将售价改为 `¥5.20`，原订单结算金额和到账仍保持原计算结果。
4. 订单详情能向用户或财务展示“本订单按创建时结算币种、结算金额和售价计算”。

#### CNYR-004：支付入口、确认页与收银台金额一致

**优先级**：P0

**需求描述**：同一订单的充值确认页、发起支付请求、第三方收银台和订单详情均使用同一结算金额；跨币种展示时，用户可见金额必须按汇率等值换算并标注实际收款。

**验收标准**：

1. 用户输入 `¥12.50` 后，人民币展示下确认页与收银台均显示 `¥12.50`。
2. 美元展示下确认页/订单详情显示 `$1.71` 并注明实际收款 `¥12.50`；收银台仍显示 `¥12.50`。
3. 切换支付方式或展示币种不改变同一订单的结算金额和实际收款。
4. 展示汇率变化不改变已创建订单的收银台金额。

### 4.3 用户余额与精度

#### CNYR-005：余额和用量仅使用展示汇率

**优先级**：P0

**需求描述**：当站点设置为人民币展示时，钱包余额、额度、模型价目和用量金额仅依据展示汇率格式化。

**验收标准**：

1. 当用户持有 `10.00` 美元等值内部额度、展示汇率为 `7.30` 时，余额显示约 `¥73.00`。
2. 管理员将展示汇率变更为 `7.00` 后，余额显示为约 `¥70.00`，不改变用户内部额度。
3. 充值售价变化不改变既有余额的展示数值。

#### CNYR-006：人民币金额不截断小数

**优先级**：P0

**需求描述**：用户输入、确认、支付和订单详情中的人民币金额必须保留业务允许的小数精度，不得以整数解析替代十进制金额。

**验收标准**：

1. 输入 `12.50` 后，系统保留 `12.50` 参与试算。
2. 输入超出精度的金额时，系统在提交前给出可读校验提示。
3. 不允许因浮点误差出现确认页、收银台和到账额度相差 `0.01` 的情况。

### 4.4 异常配置与回退

#### CNYR-007：统一校验与安全阻断

**优先级**：P0

**需求描述**：展示汇率或充值售价缺失、非法时，不允许静默使用各页面不同的默认值；新订单创建应被阻断并提示管理员处理。

**业务规则**：

1. 后台唯一的配置读取层负责默认值、格式和范围校验，前后端不得各自硬编码不同回退值。
2. 配置异常时，已创建订单仍可按快照完成或查询；仅阻断新订单。
3. 管理员看到明确的异常字段和修复建议；用户看到“充值暂不可用”的通用提示，不泄露内部配置细节。

**验收标准**：

1. 两个配置任一缺失或为非正数时，管理员无法保存。
2. 人为制造异常配置后，用户无法创建新订单，且不出现按 `1`、`7` 或 `7.3` 静默换算的金额。
3. 历史待支付订单仍显示其创建时的快照金额。

## 5. 非功能需求

1. 所有金额计算使用确定性十进制/最小货币单位策略；展示与支付不得依赖二进制浮点的偶然结果。
2. 用户可见文案覆盖控制台现有语言。
3. 汇率与售价配置变更、订单快照读取必须具备审计日志。
4. SQLite、MySQL、PostgreSQL 的订单快照持久化行为保持一致。

## 6. 验收用例表

| 编号 | 场景 | 期望 |

| U2 | 输入人民币 `12.50` 充值 | 确认页、收银台显示 ¥12.50；到账 2.50 美元等值内部额度 |
| U3 | 创建订单后售价由 5.00 改为 5.20 | 原订单快照不变；新订单按 5.20 计算 |

| U5 | 售价或展示汇率配置异常 | 新订单被阻断；用户得到通用提示；管理员看到修复项 |

## 7. 风险与依赖

- 支付金额属于高敏感财务数据，任何迁移前必须用真实订单样本核验。
- 订单快照字段需要兼容现有支付订单与多数据库迁移。
- 展示汇率与售价允许不同会增加解释成本，必须在用户确认页和管理员配置页明确提示。
- 套餐订阅场景已由 `cny-display-conversion` 定义；实现时不得产生相互冲突的换算规则。

## 8. 待确认项

1. 充值售价的计价单位是否固定为“人民币/1 美元等值内部额度”。
2. 人民币充值允许的小数位数（建议最多两位）。
3. 配置异常时是否允许管理员使用最近一次有效配置临时恢复，或必须修复后才能新建订单（本文默认必须修复）。
4. 订单快照是否向普通用户完整展示售价，还是仅展示应付金额、到账额度和创建时间。
