# Delta Spec: 支付宝通知核对与按订单到账

> 本文件聚焦支付宝支付结果确认以及向 new-api 投递易支付成功回调，是对 `../proposal.md §2.3 支付宝通知核对与按订单到账` 的精化。
> 出码与收银台见 `alipay-scan-payment.md`；渠道配置与补偿权限见 `alipay-channel-operations.md`。

## 1. 需求描述 (中文 EARS)

**主流程**:
- 当支付宝送达交易成功通知时，wechat-epay-adapter 应先验证支付宝签名，再核对应用标识、商户标识（若通知携带）、商户订单号、币种和实付金额。
- 当上述核对全部通过时，wechat-epay-adapter 应将对应支付宝订单置为已支付，并在同一可靠事务边界内创建下游通知任务。
- 当需要通知 new-api 时，wechat-epay-adapter 应向该订单保存的通知地址发送易支付成功回调，支付类型为支付宝，金额取自本地已核对订单，交易号为支付宝交易号。
- 当 new-api 返回去除空白后严格等于成功正文时，wechat-epay-adapter 应将通知标记为成功并停止自动重试。

**前置约束**:
- 若支付宝签名无效，或交易状态不是成功，wechat-epay-adapter 应拒绝业务处理，不得将订单置为已支付。
- 若应用、商户、订单号、币种或实付金额任一不匹配，wechat-epay-adapter 应将订单标记为人工审查，不得通知 new-api。
- 若通知中的商户订单号对应微信订单或不存在，wechat-epay-adapter 应拒绝自动到账。
- 若支付宝交易号缺失，wechat-epay-adapter 不得将下游通知标记为成功。

**异常与边界**:
- 当同一成功通知重复或并发到达 10 次时，wechat-epay-adapter 应最多完成一次支付状态迁移和一次有效下游到账。
- 当支付状态更新前提交失败时，wechat-epay-adapter 应回滚；当状态更新已提交时，重启后应能继续下游通知。
- 当 new-api 超时、连接失败或正文不是成功时，wechat-epay-adapter 应保留失败原因并按计划重试，不得创建新的支付订单。
- 当钱包订单支付成功时，wechat-epay-adapter 应只通知该订单的钱包地址，不得通知订阅地址。
- 当订阅订单支付成功时，wechat-epay-adapter 应只通知该订单的订阅地址，不得通知钱包地址。
- 若订单已过期或关闭后仍收到成功通知，wechat-epay-adapter 应进入人工审查，不得静默丢弃或自动到账。
- 在微信通知到达支付宝订单，或支付宝通知到达微信订单的情况下，wechat-epay-adapter 应拒绝自动到账。

## 2. 验收标准

- [ ] **正常到账**: 给定签名合法且字段全部匹配的支付宝成功通知，当适配器处理完成后，订单为已支付，且 new-api 收到支付宝类型的成功回调。
- [ ] **验签失败**: 给定无效签名，当通知到达时，订单状态不变，new-api 不被通知。
- [ ] **未成功交易**: 给定交易状态不是成功，当通知到达时，订单不得变为已支付。
- [ ] **金额或身份不一致**: 给定实付金额、币种、应用或商户与本地订单不符，当通知到达时，订单进入人工审查且无下游通知。
- [ ] **并发重放**: 给定同一成功通知并发或连续 10 次，当处理结束时，仅一次有效支付和一次有效到账。
- [ ] **事务与重启**: 给定状态更新前故障，当恢复时事务已回滚；给定状态已提交后重启，未完成通知可继续且不丢失。
- [ ] **下游失败重试**: 给定 new-api 停机或非成功正文，当其恢复后，适配器最终只成功通知一次。
- [ ] **业务隔离**: 给定钱包订单与订阅订单各一笔成功支付，当查询投递记录时，两条通知地址互不交叉。
- [ ] **渠道互斥**: 给定支付宝通知携带微信订单号，或微信通知携带支付宝订单号，当处理结束时，均未自动到账。
- [ ] **过期后付款**: 给定已关闭或过期订单随后收到成功通知，当处理结束时，订单为人工审查且未自动到账。

## 3. 范围说明

**范围内 (In Scope)**:
- 支付宝异步通知验签与业务核对、支付状态迁移、人工审查、按订单地址投递支付宝类型易支付回调、重试与幂等

**范围外 (Out of Scope)**:
- 进单与类型分流（见 `epay-alipay-intake.md`）
- 预下单与收银台展示（见 `alipay-scan-payment.md`）
- 管理查询权限、密钥存放和按渠道指标（见 `alipay-channel-operations.md`）
- 自动退款、关单对用户暴露、修改 new-api 入账公式
- 具体实现方案（由 `design.md` 承接）
