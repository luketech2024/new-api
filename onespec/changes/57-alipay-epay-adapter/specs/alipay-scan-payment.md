# Delta Spec: 支付宝扫码预下单与收银台

> 本文件聚焦支付宝当面付扫码出码和用户收银台，是对 `../proposal.md §2.2 支付宝扫码下单与独立收银台` 的精化。
> 进单校验见 `epay-alipay-intake.md`；支付成功后的验签与到账见 `alipay-settlement.md`。

## 1. 需求描述 (中文 EARS)

**主流程**:
- 当支付宝本地订单已通过进单校验时，wechat-epay-adapter 应以相同商户订单号和已核对的人民币金额向支付宝创建扫码预下单，金额精度为两位小数。
- 当支付宝返回有效二维码内容时，wechat-epay-adapter 应保存该内容，并将订单置于待支付，引导用户进入支付宝品牌收银台。
- 当订单处于待支付时，用户应能看到与订单金额匹配的支付宝二维码、商品名称、剩余有效时间和本地状态。
- 当本地订单变为已支付时，收银台应在下一次状态刷新后展示支付成功；存在已校验跳转地址时可以跳转，不得把跳转本身当成到账完成。

**前置约束**:
- 若本地订单支付类型不是支付宝，wechat-epay-adapter 不得向支付宝预下单。
- 若支付宝预下单尚未返回有效二维码内容，wechat-epay-adapter 不得将订单当作可扫码支付，也不得向用户展示伪造支付码。
- 若跳转地址不存在或未通过白名单校验，收银台应停留在结果页，不得跳转到该地址。
- 收银台访问凭据应不可猜测；页面不得暴露易支付密钥、支付宝私钥或内部管理信息。

**异常与边界**:
- 若支付宝下单失败或超时，wechat-epay-adapter 应将订单标记为创建失败或保持可重试，失败原因应对用户脱敏。
- 当相同支付宝订单重复发起预下单时，wechat-epay-adapter 应避免产生相互冲突的本地支付结果。
- 当订单过期或关闭时，收银台应停止展示可支付状态并提示重新发起支付。
- 当用户打开微信订单收银台时，wechat-epay-adapter 应展示微信支付品牌和微信二维码，不得混用支付宝文案或支付宝码。
- 在浏览器同步跳转被伪造或提前触发的情况下，wechat-epay-adapter 与 new-api 均不得据此完成到账。
- 在订单有效期内，收银台应轮询适配器本地状态，不得以客户端自行声称的支付成功修改订单。

## 2. 验收标准

- [ ] **正常出码**: 给定已校验的支付宝订单，当预下单成功时，收银台展示应付人民币金额和可扫描的支付宝码，品牌为支付宝。
- [ ] **金额一致**: 给定 `0.01`、`0.10`、`1.01` 元订单，当向支付宝预下单时，传出金额与本地原始元金额一致。
- [ ] **下单失败**: 给定支付宝侧失败或超时，当预下单返回失败时，订单不是待支付，页面不出现可付款二维码。
- [ ] **重复预下单**: 给定同一支付宝订单多次触发预下单，当查询本地结果时，不存在互相冲突的可支付结果。
- [ ] **状态刷新**: 给定本地订单已支付，当下一次收银台刷新时，页面展示支付成功且停止引导继续付款。
- [ ] **过期**: 给定订单已过期，当用户仍打开收银台时，页面停止可支付状态并提示重新发起。
- [ ] **不可信跳转**: 给定未通过校验的跳转地址，当支付成功时，页面不跳转到该地址。
- [ ] **微信收银台隔离**: 给定微信待支付订单，当打开其收银台时，页面为微信支付且二维码不是支付宝码。
- [ ] **同步跳转非到账**: 给定伪造或提前触发的浏览器跳转，当核对账户时，额度或订阅均未因该跳转而增加。

## 3. 范围说明

**范围内 (In Scope)**:
- 支付宝扫码预下单、二维码保存、支付宝品牌收银台、有效期、本地状态展示与可信跳转

**范围外 (Out of Scope)**:
- 易支付进单校验与类型分流（见 `epay-alipay-intake.md`）
- 支付宝异步通知验签、人工审查和 new-api 回调（见 `alipay-settlement.md`）
- 电脑网站跳转支付、手机网站、APP、JSAPI 等非扫码产品
- 具体实现方案（由 `design.md` 承接）
