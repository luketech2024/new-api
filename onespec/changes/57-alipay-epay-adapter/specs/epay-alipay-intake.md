# Delta Spec: 易支付支付宝进单与微信分流

> 本文件聚焦支付适配器对支付宝类型易支付订单的入口校验，是对 `../proposal.md §2.1 易支付受理支付宝并保持微信进单` 的精化。
> 与 proposal 的分工：proposal 描述双渠道进单意图；本文件描述类型分流、金额、地址允许列表和订单冲突边界。收银台出码见 `alipay-scan-payment.md`，通知到账见 `alipay-settlement.md`。

## 1. 需求描述 (中文 EARS)

**主流程**:
- 当 new-api 提交字段完整、签名有效且支付类型为支付宝的易支付订单时，wechat-epay-adapter 应校验商户身份、签名类型、金额和通知地址，并创建唯一的支付宝待支付订单。
- 当支付类型为微信且其余校验通过时，wechat-epay-adapter 应创建微信订单并进入既有微信支付流程，不得创建支付宝订单。
- 当相同商户订单号与相同关键业务字段（含支付类型、金额、通知地址）再次提交时，wechat-epay-adapter 应返回原订单的可继续支付结果，不得创建重复订单。

**前置约束**:
- 若商户 ID 与配置不一致，或签名类型不是约定的 MD5，或签名不匹配，wechat-epay-adapter 应拒绝请求且不得创建订单。
- 若支付类型既不是支付宝也不是微信，wechat-epay-adapter 应拒绝请求且不得创建订单。
- 若必填字段缺失，或金额不是大于等于 0.01 元且最多两位小数的合法十进制数，或超过配置上限，wechat-epay-adapter 应拒绝请求。
- 若通知地址不在已配置的 HTTPS 允许列表内，wechat-epay-adapter 应拒绝请求；跳转地址不可信时，wechat-epay-adapter 应拒绝或忽略该跳转，不得产生开放跳转。

**异常与边界**:
- 当金额为 `0.01`、`0.10`、`1.01` 元时，wechat-epay-adapter 应分别得到 1、10、101 分，不得出现浮点舍入差异。
- 若地址规范化后指向环回、链路本地、私网、非预期端口或越过允许路径，wechat-epay-adapter 应拒绝请求且不得访问该地址。
- 若相同商户订单号以不同支付类型、不同金额或不同通知地址再次提交，wechat-epay-adapter 应拒绝冲突请求、保留原订单并记录脱敏安全审计事件。
- 在并发提交相同订单的情况下，wechat-epay-adapter 应最多保留一个有效本地订单。
- 在支付宝必要配置缺失的情况下，wechat-epay-adapter 应拒绝新的支付宝进单，且不得因此拒绝合法微信进单。

## 2. 验收标准

- [ ] **正常支付宝进单**: 给定配置完整且字段、签名、金额、支付宝类型和允许列表地址均合法，当 new-api 提交订单时，wechat-epay-adapter 创建一条支付宝待支付订单且不发起微信下单。
- [ ] **微信回归**: 给定同样合法的微信类型请求，当 new-api 提交订单时，wechat-epay-adapter 按微信支付流程处理且不发起支付宝下单。
- [ ] **未知类型**: 给定空类型或未知类型，当提交订单时，wechat-epay-adapter 拒绝请求且订单数量不变。
- [ ] **签名场景**: 给定一份合法支付宝请求，当已签名字段被修改而签名未更新时，wechat-epay-adapter 拒绝请求且不创建订单。
- [ ] **金额边界**: 给定 `0.01`、`0.10`、`1.01` 元，当订单被校验时，持久化金额分分别为 1、10、101。
- [ ] **金额异常**: 给定三位小数、非数字、零、负数或超上限金额，当提交订单时，wechat-epay-adapter 拒绝请求。
- [ ] **地址安全**: 给定非允许列表、非 HTTPS、私网或越界地址，当提交订单时，wechat-epay-adapter 拒绝请求且不访问目标。
- [ ] **幂等场景**: 给定已存在的支付宝订单，当相同业务字段再次提交时，wechat-epay-adapter 返回原订单且订单数量不变。
- [ ] **类型冲突**: 给定已存在的微信订单号，当以支付宝类型携带相同订单号再次提交时，wechat-epay-adapter 拒绝冲突并保留原微信订单。
- [ ] **配置缺失**: 给定支付宝材料不完整而微信配置完整，当分别提交支付宝和微信订单时，前者被拒绝、后者可创建。

## 3. 范围说明

**范围内 (In Scope)**:
- 易支付进单的类型分流、签名、金额、允许列表、订单唯一性与冲突
- 钱包与订阅两条通知地址作为允许列表成员时的进单放行

**范围外 (Out of Scope)**:
- 支付宝预下单、二维码与收银台展示（见 `alipay-scan-payment.md`）
- 支付宝异步通知验签、状态机和下游回调正文（见 `alipay-settlement.md`）
- 密钥隔离、指标和人工补偿权限（见 `alipay-channel-operations.md`）
- 修改 new-api 易支付协议或入账实现
- 具体实现方案（由 `design.md` 承接）
