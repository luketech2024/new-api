# Delta Spec: 展示汇率与充值售价分离及价目跟随

> 本文件聚焦 **管理端配置语义与价目/余额展示所用汇率** 的规范变更细节，是对 `../proposal.md §2.5` 的精化。
> 收银台实付必须走售价，见订阅与充值相关 Spec；本文件禁止把两个数字都叫作汇率。国内默认牌价跟随展示汇率另排，不在本 Spec。

## 1. 需求描述 (中文 EARS)

**主流程**:
- 当管理员打开与额度展示、充值相关的设置时，**new-api 控制台**应以不同名称和示例分别说明展示汇率与充值售价。
- 当用户查看钱包余额、套餐额度或模型价目时，**new-api 控制台**应按展示汇率把内部美元额度呈现为当前展示货币。
- 当仅修改展示汇率、不修改充值售价时，**new-api** 应保持充值与订阅的应付金额、收银台金额不变。

**前置约束**:
- 若展示汇率或充值售价非正数，**new-api** 应拒绝保存或拒绝依赖该值的换算，不得当作 1 静默使用，除非产品已有明确默认值并在界面展示该默认。

**异常与边界**:
- 在展示汇率与充值售价不相等时，**new-api** 应将其视为允许的折扣或加价，不得当作配置错误拦截保存。
- 本变更不得用充值售价计算模型调用成本。
- 本变更不重算历史用量日志中的金额快照。

## 2. 验收标准

- [ ] **正常场景**: 给定管理员分别填写展示汇率与充值售价，当保存后进入设置页时，两字段标签与说明示例可区分，且都不被同时称为「汇率」。
- [ ] **正常场景**: 给定只改展示汇率，当用户查看余额和模型价目时数值随展示汇率变化；当用户查看订阅应付并拉起收银台时金额不随该次展示汇率修改而变。
- [ ] **边界场景**: 给定展示汇率与售价不相等，当管理员保存时，保存成功，充值实付按售价、余额展示按展示汇率。
- [ ] **异常场景**: 给定将展示汇率或售价改为 0 或负数，当保存或发生换算时，系统拒绝或明确报错，不得产生 0 元收款或无限额度展示。

## 3. 范围说明

**范围内 (In Scope)**:
- 管理端两个数字的命名、说明与校验
- 余额、套餐额度、模型价目使用展示汇率

**范围外 (Out of Scope)**:
- 未手改国内默认牌价跟随展示汇率（另排）
- 订阅余额扣减公式（`subscription-balance-pay.md`）
- 通道下单币种（`payment-channel-settlement.md`）
- 账本存储单位改造
- 具体配置键名（由 `design.md` 承接）
