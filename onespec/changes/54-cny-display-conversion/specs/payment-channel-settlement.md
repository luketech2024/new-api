# Delta Spec: 各在线通道收款金额与币种一致

> 本文件聚焦 **订阅在线支付下单** 的规范变更细节，是对 `../proposal.md §2.3` 的精化。
> 用户界面如何显示应付金额见 `subscription-due-display.md`；本文件约束第三方实际收款。

## 1. 需求描述 (中文 EARS)

**主流程**:
- 当用户为同一套餐选择易支付或其他已启用在线通道下单时，**new-api** 应按套餐 **`price_amount` + `currency`** 的结算含义向各通道提交等值收款金额。
- 当管理员仅将额度展示类型在人民币与美元之间切换、不修改套餐价格与结算币种时，**new-api** 应保持各通道收款金额与币种不变。

**前置约束**:
- 若套餐未启用或价格低于通道允许下限，**new-api** 应拒绝下单且不得创建待支付订阅订单。
- 若所选支付方式未对应当前站点已启用方法，**new-api** 应拒绝下单。

**异常与边界**:
- 若某通道要求显式币种代码，**new-api** 应按套餐结算币种填写，不得读取额度展示类型来决定币种。
- 若通道以最小货币单位收款，**new-api** 应按该通道既有精度规则换算，不得把展示汇率乘进下单金额。
- 在微信支付收银台展示的金额，**new-api** 应与套餐结算价一致；本变更不修改验签、解密与入账幂等行为。
- 本变更不自动改写第三方后台已创建商品的标价；若第三方商品价与套餐结算价不一致，**new-api** 应在设计中明确以套餐结算价或拒绝下单的策略，不得静默按展示类型改币种。

## 2. 验收标准

- [ ] **正常场景**: 给定套餐 `currency=CNY`、价格 20，当用户通过易支付拉起微信收银台时，应付金额为 20.00 元人民币。
- [ ] **正常场景**: 给定套餐 `currency=USD`、价格 20、售价 7.3，当用户通过易支付拉起微信时，收款约为 146 元人民币；仅切换展示类型后收款不变。
- [ ] **边界场景**: 给定先将展示类型设为人民币再改为美元且套餐价格与结算币种不变，当再次下单时，易支付收款与改展示前一致。
- [ ] **异常场景**: 给定套餐价格低于 0.01，当用户请求在线支付时，系统拒绝下单且不创建待支付订单。
- [ ] **异常场景**: 给定支付方式不在已配置方法中，当用户请求支付时，系统拒绝且不向第三方创建收款。

## 3. 范围说明

**范围内 (In Scope)**:
- 订阅场景下易支付（含微信、支付宝）的下单金额
- 「展示设置变化不得改变收款」不变式

**范围外 (Out of Scope)**:
- **Creem**（境外通道，本变更不改）
- 钱包充值下单金额公式（`topup-due-display.md`，充值仍按额度数量×售价）
- 微信支付适配器通知地址、验签与回调（既有支付变更）
- Stripe 等以预置 Price ID 计价的通道
- 具体请求字段名（由 `design.md` 承接）
