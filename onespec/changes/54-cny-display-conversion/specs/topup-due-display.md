# Delta Spec: 充值到账与实付分列展示

> 本文件聚焦 **添加资金页** 的规范变更细节，是对 `../proposal.md §2.4` 的精化。
> 订阅应付与余额兑换不在本文件；展示汇率与售价的管理端定义见 `admin-rate-semantics.md`。

## 1. 需求描述 (中文 EARS)

**主流程**:
- 当用户打开添加资金并查看档位时，**new-api 控制台**应同时展示到账额度（按展示货币）与实付金额（按充值售价计算的本地收款），并带上相应货币单位。
- 当用户选择某档或输入自定义到账额度时，**new-api 控制台**应使输入框单位与档位到账数字使用同一展示货币，实付金额随售价与折扣更新。
- 当用户用步进调整自定义金额时，**new-api 控制台**应使用独立 −/+ 按钮（约 40×40 px），输入框标明展示货币符号，应付金额作为输入框下方辅助文案；不得使用浏览器原生数字微调箭头。
- 当确认支付时，**new-api 控制台**应继续按到账额度对应的内部数量向后端提交，实付与收银台一致。

**前置约束**:
- 若充值售价未配置或非正数，**new-api 控制台**不得把到账数字当作实付展示。
- 若用户输入低于最小充值数量，**new-api** 应沿用既有最小充值限制；自定义金额的 − 在已达下限时置灰。

**异常与边界**:
- 当展示货币为人民币时，**new-api 控制台**不得在选中已换算档位后仍在自定义输入框显示未换算的内部美元数量。
- 当用户点击自定义金额 +/− 时，**new-api 控制台**应按 **1 个内部充值单位** 增减（美元展示步进 $1；人民币展示步进展示汇率对应的到账数字），不得改变实付计算公式。
- 当展示汇率与充值售价不相等时，**new-api 控制台**允许到账与实付数字不同，但必须用「到账」「实付」文案区分，且实付不得改用展示汇率计算。
- 当存在档位折扣时，**new-api 控制台**应在实付上体现折扣后金额，到账仍为该档对应额度。
- 本变更不把档位配置列表改写成乘过汇率的数字。

## 2. 验收标准

- [ ] **正常场景**: 给定展示货币为美元、档位内部数量为 7、售价为 7，当用户查看该档时，到账标明美元 7、实付标明人民币 49，不得只显示无单位的 7 与 Pay 49。
- [ ] **正常场景**: 给定展示货币为人民币、展示汇率为 7、同一档内部数量为 7，当用户选中该档时，到账与自定义输入均为人民币 49 量级，实付按售价计算，输入框不得仍为 7。
- [ ] **正常场景**: 给定自定义金额输入框，当用户查看与点击步进时，输入框带 $ 或 ¥ 前缀，−/+ 热区约 40×40 px，应付金额在输入框下方；不得出现浏览器原生上下箭头。美元展示下点 + 从 7 变为 8；已达最低充值额时 − 置灰。
- [ ] **边界场景**: 给定展示汇率为 7、充值售价为 7.3，当用户选择内部数量 7 的档位时，到账按汇率展示，实付按 7×7.3 计算，不得把实付也变成按 7 计算。
- [ ] **边界场景**: 给定切换展示货币前后，当读取充值档位配置时，列表仍为原内部数量，不得被改写为乘汇率后的值。
- [ ] **异常场景**: 给定售价无效，当用户打开添加资金时，系统不得用错误单位展示实付，应阻断支付或明确提示配置错误。

## 3. 范围说明

**范围内 (In Scope)**:
- 添加资金档位、自定义金额、待支付/确认支付文案中的到账与实付
- 人民币展示下输入单位与档位对齐
- 自定义金额输入交互（货币前缀、大号 −/+、应付金额下移）；对照原型 `onespec/prototype/topup-custom-amount-preview.html` 方案 A

**范围外 (Out of Scope)**:
- 订阅弹窗（`subscription-due-display.md`）
- 后端 `amount` 请求字段含义（仍为内部充值数量，HOW 见设计）
- 兑换码兑换额度流程
- 支付方式按钮样式
