# Delta Spec: 订阅应付金额与套餐价格展示口径

> 本文件聚焦 **订阅购买弹窗、套餐卡片、订阅管理价格列** 的规范变更细节，是对 `../proposal.md §2.1` 的精化。
> 与 proposal 的分工：proposal 描述跨模块的价格口径统一；本文件只约束**用户可见应付金额/套餐价格**如何按展示货币渲染。余额扣减见 `subscription-balance-pay.md`，通道实收见 `payment-channel-settlement.md`。

## 1. 需求描述 (中文 EARS)

**主流程**:
- 当套餐结算币种为美元（`currency` 缺省或 `USD`）且站点展示改为人民币时，**new-api 控制台**应按充值售价展示应付人民币，且收银台实收与余额扣减相对改展示前保持不变。
- 当套餐结算币种为人民币时，**new-api 控制台**应使用人民币符号展示价格原值；切到美元展示时应按充值售价换算并注明实扣人民币，收银台与余额扣减仍不变。
- 当管理员切换额度展示类型且不修改套餐价格与结算币种时，**new-api** 应只改变展示符号与换算结果，不得改写已保存的价格数字与 `currency`。

**前置约束**:
- 若充值售价未配置、非正数或无法用于换算，**new-api 控制台**不得把套餐价格按美元额度直接拼美元符号展示。
- 若套餐价格低于允许的最小收款金额，**new-api** 应沿用既有「金额过低」拒绝规则，不得生成误导标价。

**异常与边界**:
- 若换算结果因舍入与收银台分位相差，**new-api 控制台**应以收银台实收为对齐基准展示应付，并避免二次乘展示汇率。
- 在套餐额度与应付金额同时出现在弹窗时，**new-api 控制台**应按既有额度展示规则渲染套餐额度，不得随本 Spec 的应付金额修正而改写额度数字。
- 若某套餐名称与价格配置明显不是同一货币口径，**new-api** 仍按配置价格展示与收款，不得自动改写该配置。

## 2. 验收标准

- [ ] **正常场景**: 给定站点展示货币为人民币、套餐价格为 20 且微信实收 20 元，当用户打开购买弹窗时，应付金额显示为人民币 20.00，不出现美元符号，且与收银台相同。
- [ ] **正常场景**: 给定同一套餐、展示货币改为美元、充值售价为 7.3，当用户打开购买弹窗时，应付金额按 20÷7.3 展示为约 2.74 美元并注明实扣 20 元人民币，收银台仍为 20 元。
- [ ] **边界场景**: 给定只修改展示汇率、不修改充值售价与套餐价格，当用户再次打开弹窗并拉起支付时，应付金额与收银台金额相对改前保持不变。
- [ ] **边界场景**: 给定切换展示货币前后，当查询套餐价格配置时，保存值仍为 20，不得变为 140。
- [ ] **异常场景**: 给定套餐额度在人民币展示下原为约 20.02，当完成本变更后再次打开弹窗时，套餐额度仍为该值。

## 3. 范围说明

**范围内 (In Scope)**:
- 订阅购买弹窗应付金额、前台套餐卡片价格、订阅管理列表价格列的符号与换算
- 美元展示下对应付金额的实扣人民币附注

**范围外 (Out of Scope)**:
- 余额所需额度的计算（`subscription-balance-pay.md`）
- 各通道向第三方下单的币种与金额（`payment-channel-settlement.md`）
- 充值档位展示（`topup-due-display.md`）
- 具体组件与格式化函数选型（由 `design.md` 承接）
