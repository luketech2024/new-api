# Delta Spec: 余额购买订阅与在线支付同价

> 本文件聚焦 **用钱包额度兑换订阅** 的规范变更细节，是对 `../proposal.md §2.2` 的精化。
> 应付金额如何显示见 `subscription-due-display.md`；本文件约束扣减数量与「余额支付需要」展示必须与在线实付同价。

## 1. 需求描述 (中文 EARS)

**主流程**:
- 当用户选择余额支付购买订阅时，**new-api** 应按该套餐 **结算币种** 折算所需钱包额度（USD：价格×每美元额度；CNY：价格÷充值售价×每美元额度），再扣减并开通订阅；折算不得读取额度展示类型。
- 当控制台展示「余额支付需要」时，**new-api 控制台**应使用与应付金额相同的货币与数值口径。

**前置约束**:
- 若套餐不允许余额支付，**new-api** 应拒绝兑换并提示该套餐不允许使用余额兑换。
- 若折算后所需额度大于用户可用额度，**new-api** 应提示余额不足，不得扣减部分额度，不得创建已支付订阅。
- 若充值售价未配置或非正数，**new-api** 应拒绝余额兑换并给出可读原因，不得回退为「价格×每美元额度」的错误口径。

**异常与边界**:
- 若套餐价格为 0，**new-api** 应按既有规则不扣额度或按 0 额度处理，不得产生负向额度。
- 若折算出现溢出或非有限数字，**new-api** 应拒绝本次兑换并记录可审计错误，不得静默截断为错误扣减。
- 在管理员未配置额外折扣或加价时，**new-api** 应保证余额路径应付与在线收银台实收对用户而言同价。
- 本变更不重算历史已用余额购买的订单。

## 2. 验收标准

- [ ] **正常场景**: 给定套餐在线实收 20 元人民币、展示汇率为 7、每美元额度单位为站点配置值，当用户打开购买弹窗时，「余额支付需要」显示为 20 元人民币而不是约 140 元。
- [ ] **正常场景**: 给定用户额度不少于按充值售价折算的所需额度，当用户确认余额支付时，系统扣减该折算额度并开通订阅，扣减数量不得等于「价格×每美元额度」且未除以售价。
- [ ] **边界场景**: 给定用户额度恰好等于所需额度，当用户余额支付时，支付成功且剩余额度为 0。
- [ ] **异常场景**: 给定用户额度小于所需额度，当用户点击余额支付时，系统提示余额不足，用户额度不变，不产生成功订阅。
- [ ] **异常场景**: 给定未配置有效充值售价，当用户尝试余额支付时，系统拒绝并提示配置错误类原因，不得按 7 倍口径扣款。

## 3. 范围说明

**范围内 (In Scope)**:
- 余额兑换订阅的额度折算、不足校验、控制台「必需/需要」展示
- 与在线实付同价的不变式

**范围外 (Out of Scope)**:
- 在线通道向微信/Creem 下单金额（`payment-channel-settlement.md`）
- 充值获得额度的计算（`topup-due-display.md`）
- 额度列存储类型改造与历史订单重放
- 具体折算公式实现（由 `design.md` 承接，且须使用项目既有额度安全换算约束）
